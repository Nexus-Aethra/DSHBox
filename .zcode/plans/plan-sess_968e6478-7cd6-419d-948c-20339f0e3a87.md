# 全量递归导出：模板 + 插件 + 数据 + harness（一次性自包含）

## 目标
`dshbox template export <name>` 产出一个 gzip tarball，包含接收方重建模板所需的一切——harness 源码、所有 Reference 插件/技能、所有 Snapshot 数据、模板 manifest。**不依赖网络、不依赖已有本地状态**。

`dshbox template import <tarball>` 把它们全部重建，已存在的部分跳过。

## Tarball 格式 (`format: "dsh-template-export"`, `version: 2`)

```
my-template.tar.gz
├── manifest.json             ← 格式声明 + 元数据
├── template/
│   ├── script.dsh            ← 脚本型模板 body（可选）
│   └── list.json             ← TemplateResourceList（可选，built 时）
├── runtimes/<version>/       ← harness 源码树（从 <root>/runtimes/<version>/source/ 拷贝，跳过 .git/）
├── plugins/<name>/...        ← 每个 Reference 插件的源码树
├── skills/<name>/...         ← 每个 Reference 技能
└── data/<hex_digest>/...     ← 每个 Snapshot 数据载荷
```

**Manifest JSON:**
```json
{
  "format": "dsh-template-export",
  "version": 2,
  "name": "my-template",
  "base": "github.com/deepseek-ai/deepseek-harness:latest",
  "profile": "web",
  "harnessRef": "latest",
  "harnessFrom": "github.com/deepseek-ai/deepseek-harness:latest",
  "harnessCommit": "deadbeef...",
  "createdAt": 1787025021,
  "exportedAt": 1787027000,
  "built": true,
  "resources": [
    {"mode": "reference", "kind": "plugin", "name": "dsh-better-sidebar",
     "version": "0.13.0", "entryId": "img-xxx"},
    {"mode": "snapshot", "kind": "data", "name": "seed.yaml",
     "digest": "<16hex>", "destination": "@profile/seed.yaml"}
  ],
  "dataDigests": ["<16hex>"]
}
```

## 导出流程（重写 `export_template`）

1. 读 `TemplateIndex` → 拿到 entry（`id`, `built`, `harness_ref`, `profile`）
2. 读 `list.json`（`TemplateResourceList`）→ 提取 `resources[]`、`harness_ref`、`base`、`labels`
3. 打开 gzip tarball，依次追加：
   - `manifest.json` — 含所有元数据
   - `template/list.json` 或 `template/<name>.dsh` — 模板主体
   - `runtimes/<version>/` — 用 `append_plugin_archive` 打包 harness 源码树（跳过 `.git/`，复用现有 helper）
   - `plugins/<name>/`、`skills/<name>/` — 用 `append_plugin_archive` 打包每个 Reference 资源的 `source_path`
   - `data/<digest>/` — 用 `append_plugin_archive` 打包每个 Snapshot 的 store 目录
4. 写文件，返回路径

## 导入流程（重写 `import_template`）

1. 解压 tarball 到 staging
2. 读 `manifest.json` → 识别格式：
   - `format == "dsh-template-export"` 且 `version == 2` → 走富导入
   - 否则 → 走 legacy 导入（原行为，只接受 `.dsh` 单文件）
3. **富导入**（每步幂等）：
   a. **Harness**：检查 `<root>/runtimes/<version>/source/.dshbox-runtime.json`；若存在则跳过，否则从 `runtimes/<version>/` 拷贝到目标目录并写 `.dshbox-runtime.json`（含 version/from/commit）
   b. **模板**：如果 `built` 则 `write_built_template`（用 list.json body）；否则 `write_template_with_entry`（用 script.dsh）
   c. **插件/技能**：对每个 Reference 资源，先 `find_repository_entry_by_identity(root, kind, name, version)` 查重；命中且无 diagnostic 则跳过，否则调用新的 `import_extension_to_repository`（同步版，不需要 TaskContext）把 `plugins/<name>/` 拷入 repository 并写入 index.json
   d. **数据**：对每个 Snapshot digest，检查 `<root>/data/<digest>/`；存在则跳过，否则从 `data/<digest>/` 拷入并更新 `data/index.json`

## CLI

- `dshbox template export <name> [dest]` — 保持不变
- `dshbox template import <tarball> [--name <name>]` — 保持签名不变；`--conflict` 逻辑在富导入中通过 `find_repository_entry_by_identity` 查重 + 跳过实现（不需要 expose 给 CLI）

## 不做

- **不递归打包 from 链** —— harness runtime 是终点，FROM 链在构建时已展开（脚本的 FROM 已在 build 时 resolved 到具体 harness_ref）
- **不嵌入容器实例** —— 只导出 template + 依赖
- **不改 `write_built_template` / `write_template_with_entry`**

## 验证计划

1. `dshbox template export dshbox-plugin-chains /tmp/chain.tar.gz`
2. `tar tzf /tmp/chain.tar.gz | head -30` — 确认 manifest.json、template/list.json、runtime/、plugins/*/、data/*/ 都在
3. `dshbox template rm dshbox-plugin-chains`
4. `dshbox template import /tmp/chain.tar.gz`
5. `dshbox template show dshbox-plugin-chains` — 5 个资源
6. `dshbox template info dshbox-plugin-chains` — createdAt + harnessRef + 5 resources
