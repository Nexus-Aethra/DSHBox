## 插件引用计数修复 — 复合计数器 + 完整增量/减量路径

### 现状（已实证）

| 操作 | counter 行为 | 期望 |
|---|---|---|
| 容器从模板创建（materialise） | ✅ +1（`link_repository_extension`） | +1 |
| `plugin install <container> <source>`（CLI 直接装） | ❌ **不 +1** | +1 |
| 容器 rm | ✅ -1（遍历 `extensions.json`） | -1 |
| `plugin rm <container> <name>`（单容器卸载） | ❌ **不 -1** | -1 |
| 模板 rm（无容器在用时） | ❌ **不 -1** | -1（模板的引用） |
| `plugin prune` | ❌ 永远"无 unused"（受 bug 影响） | 删 count=0 的 |
| Skill 计数（record 有 `repository_id`） | ❌ 减量是 +0 增量 | 不计入或正确计入 |

### 用户要求（综合两条诉求）

1. **复合计数器**——同一插件可被模板和容器各自单独引用，counter 必须分别记录两类引用
2. **模板 / 容器删除时必须减量**

### 设计

#### 数据模型（`box-extensions/src/lib.rs`）

`references.json` 由当前 `BTreeMap<entry_id, u32>` 改为：

```rust
#[derive(Default, Serialize, Deserialize)]
pub struct ReferenceCount {
    pub containers: u32,   // 容器直接引用数（per-record extensions.json）
    pub templates: u32,    // 模板引用数（built-template list.json 中的 Reference）
}
pub type References = BTreeMap<String, ReferenceCount>;
```

每个 entry 在 `references.json` 里有 `{"containers": N, "templates": M}`。`unused` 当两者都为 0。`reference_count()` 返回 `containers + templates`（兼容老 API，但语义不变）。

向后兼容：`#[serde(default)]` 让旧版单数字格式降为 0 + 0；下次写入时升级。

#### 计数语义

| 事件 | 增/减 | 字段 |
|---|---|---|
| `materialise_built_template` 链接 reference plugin | +1 templates | templates |
| `materialise_script_template` 链接 repository plugin（`install_from_repository`） | +1 templates | templates |
| `link_repository_extension` 由模板自动调用（built + script） | +1 templates | templates（**改**：现在记 templates 不是 containers） |
| `install_container_extension`（CLI `plugin install <container> <source>`） | +1 containers | containers |
| `container_plugin_add`（同上的别名） | +1 containers | containers |
| `delete_container_rpc`（已有） | -1 containers | containers |
| `remove_repository_plugin`（修复） | -1 containers | containers |
| `remove_template`（修复：遍历 list.json 的 Reference） | -1 templates | templates |

Skill 计数策略：保持当前"不增不减"行为（不计入 counter），但需要在 `delete_container_rpc` 的循环里**跳过** `kind == Skill` 的 record，免得无中生有地减 0。代码改动仅一行 `if record.kind == ExtensionKind::Plugin`。

#### Counter API 改造

```rust
pub fn increment_reference(runtime: &Path, entry_id: &str, kind: ReferenceKind) -> Result<(), String>;
pub fn decrement_reference(runtime: &Path, entry_id: &str, kind: ReferenceKind) -> Result<u32, String>;

pub enum ReferenceKind { Container, Template }
```

`unused_repository_ids` 维持返回 `containers == 0 && templates == 0` 的 id 列表。`reference_count(runtime, entry_id)` 返回 `containers + templates`，**保留旧签名**（向后兼容）。

#### 修复点

**`box-extensions/src/lib.rs`**
- 重写 `references.json` 数据结构（`ReferenceCount`）
- 改 `increment_reference` / `decrement_reference` 签名，加 `ReferenceKind`
- `read_references` 升级时兼容旧格式（`#[serde(default)]`）

**`dshboxd/src/extensions.rs`**
- `link_repository_extension` (line 152)：`increment_reference(..., ReferenceKind::Template)`（注意：链接总是从模板触发的；直接 install 走另一条路径）
- `install_container_extension` (line 489)：在 `install_container_plugin` 成功后，**当 source 是已存在 repository id 时**调 `increment_reference(..., ReferenceKind::Container)`。否则（local/tarball，未入 repo）跳过——但需保证 record 里不写 `repository_id`，否则 `delete_container_rpc` 会去 -1 一个不存在 +1 的 id。
- `remove_repository_plugin` (line 647)：先读容器 record 找 `repository_id`，删 record 后调 `decrement_reference(..., ReferenceKind::Container)`

**`dshboxd/src/image.rs`**
- `remove_template` (line 1342)：删除前遍历 `TemplateResourceList` 的 `Reference` 项，每项 `decrement_reference(..., ReferenceKind::Template)`。在索引里删除 entry 之前做。

**`dshboxd/src/dispatch.rs`**
- `delete_container_rpc` (line 815)：循环里加 `if record.kind == ExtensionKind::Skill { continue; }`（防止 skill 错减）

**`box-state/src/lib.rs`**
- `ResourceSnapshot.repository_references`（line 74）：同步新格式，序列化时把每个 entry 摊平为 `containers + templates`（UI 端用 sum 展示）

#### 测试

- 在 `box-extensions` 加测试：旧 `u32` 格式读入 → 视为 `containers: N, templates: 0`；新格式写盘 roundtrip
- 在 `dshboxd/extensions.rs::tests` 加测试：`link_repository_extension` + `remove_repository_plugin` 平衡；`materialise_script_template` 模板计数与 `remove_template` 平衡

### 验证步骤（实现完后跑）

1. 清空 `repository/`
3. `plugin import <dir>` → counter 全空 ✅
4. 装脚本模板 → counter 全空 ✅
5. 容器 A 从模板创建 → `templates: 1` ✅
6. 容器 B 也从模板创建 → `templates: 2` ✅
7. `plugin install B <source>`（直接装）→ `containers: 1`（B 单独记），`templates: 2` ✅
8. 删 A → `templates: 1`（B 仍记 templates）✅
9. 删 B → `templates: 0`，`containers: 0` ✅
10. `plugin prune` → 成功删 ✅
11. 模板 rm：装模板，删所有容器后模板 rm → `templates: 0` ✅
12. Skill 不影响 counter ✅
13. 容器删后模板仍在 → counter = templates: 1 ✅

### 不做

- 不重写 `references.json` 文件格式（保持 JSON，兼容老客户端可读为 0）
- 不改 RPC 接口名（`list_repository_extensions` 仍返回 `ReferenceExtension`，counts 单独通过 `resource_state` 暴露）
- 不动 snapshot / data store 计数（已确认按"无引用计数，仅 owner GC"处理）
