# 2026-11-04 — feat/node-core 实现级设计（路线图 A 阶段）

> 状态：**实现中**。本文是 [`2026-11-04-node-architecture-roadmap.md`](2026-11-04-node-architecture-roadmap.md)
> 里 A 分支 `feat/node-core` 的施工说明。范围严格限制在「控制平面骨架 + 注册握手」，
> **不动**容器启动路径、不动 `RuntimeKind`、不下沉任何现有文件操作。

## 目标（本分支做完能验证什么）

1. daemon 拥有一张持久化的 **NodeRecord** 表，内建一个 `kind: host` 的宿主 node。
2. 一个最小 **box-helper** 可执行文件能在 Linux（本机 WSL2 guest）里启动，
   用一次性 enroll 凭证完成注册，拿到限权 session token，
   订阅 `GET /events`、定期心跳、响应 echo、回报日志。
3. 控制平面能列出 node、看到在线/离线状态、注销 node；token 轮换后可重新注册。
4. host 容器启动/停止/rebuild/delete **零回归**（本分支不碰那条路径）。

明确**不做**：异步镜像构筑（B）、模板→node 调度与 `runtime`→`node_id` 迁移（C）、
面板（D）、docker/VZ 供给适配器、把 DSH 烘进镜像、改动 `box-store` schema。

## 现状约束（已核对代码）

| 机制 | 位置 | 对设计的影响 |
|---|---|---|
| RPC 入口 | `main.rs:267-312` | `POST /rpc`，body 里的 `token` 必须等于 discovery 主 token；**全局权限**，不能下发到 guest |
| SSE | `main.rs:239-264,333-359` | `GET /events?token=<主token>`；snapshot 里目前只有 tasks/resources |
| 事件枚举 | `events.rs:18-76` | `#[serde(tag="event", rename_all="lowercase")]`，`event_name()` 是 wire 名；新增变体必须同步 |
| 状态容器 | `state.rs:188-245` | `DaemonState` 是 `Arc` 共享；新增字段要放进 `load()` |
| 持久化 | `box-foundation::collection::Collection<T>`、`box-store::open_document_store_for_paths` | 用文档存储，**不改 `PRAGMA user_version`**；`Collection::memory` 可用于「无 runtime」降级与单测 |
| 时间 / id | `now_seconds()`、`uuid::Uuid::new_v4()` | 都已在 dshboxd 依赖里 |
| daemon 重启 | `discovery.json` 每次轮换 token 与端口 | 需要 `session_epoch` + 重新 enroll，否则 helper 永久掉线 |

## 数据模型

```rust
// src-tauri/crates/dshboxd/src/nodes.rs（新模块）
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct NodeRecord {
    pub id: String,                    // uuid；host node 固定为 "host"
    pub kind: String,                  // "host" | "wsl2" | "libkrun" | "vz" | "docker"
    pub platform: String,              // 例 "windows-x64" / "linux-x64"
    pub status: NodeStatus,            // registering | online | offline | draining | failed
    pub capabilities: Vec<String>,     // exec, build, image-export, copy, dsh-host
    pub control_url: Option<String>,   // helper 回连地址（host node 为 None）
    pub session_epoch: u64,            // daemon 每次启动 +1；心跳带 epoch，旧 epoch 拒绝
    pub enrolled_at: Option<u64>,
    pub last_seen: Option<u64>,
    pub helper_version: Option<String>,
    pub backend_ref: Option<String>,   // distro 名 / container id；A 阶段不读
    pub host_node: bool,               // 内建、不可注销
}

#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "lowercase")]
pub enum NodeStatus { Registering, Online, Offline, Draining, Failed }
```

约束：

- `host_node` 的 `NodeRecord` 在 `DaemonState::load()` 里 **upsert 一次**（幂等），
  `status=online`、`control_url=None`、`host_node=true`。它代表当前 daemon 进程，
  不是回连注册出来的，也不参与心跳超时。
- **不存 DSH、不存插件**：那是 `NodeArtifact`（B）与 profile（C）的事。
- `NodeStatus` 用小写 wire 形态（与 `box-scheduler` 的 task status 一致），单测固定。

### 凭证（两级）

```
enroll_token   一次性、短 TTL（默认 300s），只用于 node_register
               A 阶段由 node_enroll RPC 生成（仅主 token 可调），不入 NodeRecord
session_token  限权：仅 node_heartbeat / node_report / node_echo / node_deregister
               + GET /events?token=...
               A 阶段由 daemon 生成 uuid，随 node_register 返回；仅保存在
               NodeSession 内存表（node_id → token + epoch），不落盘
               daemon 重启即失效 → helper 用 enroll_token 重新注册
```

**主 token 永不进 guest**：`main.rs` 的全局 token 检查对 `/rpc` 保持不变；
限权 token 走一条**独立校验分支**，只放行白名单方法。这样即使 helper 被攻破，
也拿不到 `delete_container`、`enqueue_*` 等控制面能力。

## RPC 契约（新增，全部走 `POST /rpc`）

| method | 凭证 | 参数 | 返回 |
|---|---|---|---|
| `node_enroll` | 主 token | `{ kind, platform, capabilities?, nodeId? }` | `{ enrollToken, controlUrl, epoch, expiresAt }` |
| `node_register` | `enrollToken`（body 内） | `{ enrollToken, nodeId, kind, platform, capabilities, helperVersion }` | `{ nodeId, sessionToken, epoch, heartbeatSeconds }` |
| `node_heartbeat` | session token | `{ epoch }` | `{ ok, epoch, status }` |
| `node_list` | 主 token | — | `NodeRecord[]`（不含任何 token） |
| `node_get` | 主 token | `{ id }` | `NodeRecord` |
| `node_echo` | session token | `{ text }` | `{ text, nodeId }` |
| `node_report` | session token | `{ level, line }` | `{ ok }`（写进 daemon tracing + `task_log` 风格日志） |
| `node_deregister` | session token 或主 token | `{ id }` | `{ ok }`（host node 拒绝） |

`node_register` 成功后广播 `node_registered`；状态迁移广播 `node_status`；
`node_report` 广播 `node_log`。三个新 `DaemonEvent` 变体在 `events.rs` 同步
`event_name()`。SSE snapshot 增加 `"nodes": NodeRecord[]`，让 helper 一连上
就能看到自己的注册结果（前端 `useTasks` 不认识的事件名会被忽略，不回归）。

## 状态机与超时

```
(node_enroll) → registering  --node_register-->  online
                                   ↑                │
                                   │ 心跳/重连      │ 3× heartbeatSeconds 无心跳
                                   └────────  offline ──node_deregister──> (删除)
```

- `heartbeatSeconds = 30`，`offline` 阈值 `90s`（3 次）。
- **offline 保留 NodeRecord 与 backend_ref**，不删；只有显式 `node_deregister` 删除。
- **进程重启即 demote**：session 只存在内存里，所以重启后上一个进程写下的
  `online` 从进程消失那一刻起就是假的。`NodeManager::load()` 在 upsert 完 host
  节点后立刻把所有非 host 的 `online` 改成 `offline`（记录与 `backend_ref`
  保留，重新 enroll 的 helper 直接回到 online），而不是等最长一个巡检周期
  （60s + 90s 阈值）才说真话。这不是猜测：没有任何连接能跨 daemon 进程存活。
- 后台巡检线程每 **60s** 扫一次（`main.rs` 的 60×1s 睡眠，每秒检查一次 shutdown
  标志，daemon 退出时线程随之结束），把超过 90s 无心跳的 online → offline 并广播。
  因此最长发现延迟是 90s + 60s = 150s——要缩短就同时改这两个常量，别只改阈值。
- `epoch` 不匹配的会话**先在校验层被拒**：`/rpc` 直接 `401`（这个 token 不属于
  当前 daemon 进程）。若 epoch 通过校验但节点落后（业务层），`node_heartbeat` 另返回
  `{"ok":false,"error":"stale epoch; re-enroll and register again"}`。
  两级刻意分开：401 是「凭证无效」，业务层错误是「凭证有效但状态过期」。
  helper 两种情况都走重新 enroll/register，判断条件是错误文本含 `epoch`/`401`/`session`。

## helper 形态（A 阶段最小可执行）

- 位置 `src-tauri/crates/dshboxd/src/bin/box-helper.rs`？**不**——dshboxd 是单 bin crate。
  另起一个 workspace 成员 `src-tauri/crates/box-helper/`（纯 Rust，只依赖
  `serde/serde_json/uuid` 与可选 `ureq`；不发 Tokio、不引入 Tauri）。
  产物 `box-helper` 静态可执行文件，A 阶段用 `cargo build -p box-helper` 手工编到
  WSL Linux 里跑；**不进安装包、不改 release workflow**。
- 启动参数：`box-helper --enroll <token> --control <url> --node-id <id> --kind <kind>
  --platform <plat>`（或等价的 `/etc/dshbox/helper.json`，A 阶段先支持参数形式）。
- 主循环：
  1. `POST /rpc method=node_register` → 拿 `sessionToken/epoch`
  2. `GET /events?token=<session>` 长连接（独立线程），收到 `node_registered` 打印
  3. 每 30s `node_heartbeat`
  4. 收到 `node_echo` 请求（A 阶段由 `node_report` 触发一次自测 echo 并回报日志）
  5. 断线/401/stale epoch → 重新注册（指数退避，上限 30s）
- A 阶段**不执行任何文件操作**：`echo` 只回显字符串，`report` 只写日志。
  「所有操作下沉」从 B 阶段才开始。

## 认证实现（关键，避免破坏现有 RPC）

`main.rs::handle_http` 现在的顺序是：解析请求 → SSE 分支（比较主 token）→
`POST /rpc` 分支 → 读 body → 解析 JSON → 比较 `request["token"]` 与主 token → dispatch。

改法（**最小侵入**）：

```rust
let supplied = request["token"].as_str();
let is_main = supplied == Some(token);
let is_node = !is_main && state.nodes.validate_session(supplied, method);
if !is_main && !is_node { 401 }
if is_node && !NODE_METHODS.contains(method) { 403 }
```

- `NODE_METHODS` 是 `node_heartbeat/node_report/node_echo/node_deregister` 白名单。
- `node_register` 用 `enrollToken` 而非 `token` 字段，走同一入口但在 dispatch 内单独校验；
  `node_enroll` 只允许主 token。
- SSE 的 `?token=` 接受 **主 token 或任一有效 session token**（同一个 `validate_session`），
  **但两者的载荷不同**：主 token 拿到原有的完整 snapshot（`tasks`/`resources`/`nodes`）
  与全部事件；session token 只拿到 `{"nodes": [...]}` 以及 `is_node_event()` 为真的
  三个 node 事件。这不是洁癖：`tasks` 里带每个任务的工作目录、错误字符串和日志尾部，
  正是白名单要挡的控制面状态——若照发，泄漏一个 helper 凭证就等于泄漏整个控制面，
  而且还不用调用任何被禁方法。过滤入口是 `DaemonEvent::is_node_event()`，与
  `event_name()` 相邻放置，新增 node 事件忘了加入集合时一眼可见。
- **按节点隔离**：session 订阅者只收自己节点的事件与记录（`SseScope::allows` /
  `SseScope::node_id`），不是"所有 node 事件"。`node_log` 的 `line` 完全由另一个
  guest 控制，全局广播等于让一个 guest 往另一个 guest 的视图里写任意文本。
- **撤销要真的撤销**：session 在连接建立时校验一次，而 `node_deregister` 之后
  它才失效。只在建立时校验 = 撤销永不生效——被注销的 helper 只要 socket 还开着
  就能一直收自己节点的事件。转发循环用 `recv_timeout(5s)` 周期性调
  `SseScope::still_valid`（`NodeManager::has_session`），撤销或 daemon 重启都会
  在 5s 内关闭已开的流。
- **`host` 是保留 id**：`node_enroll` 直接拒绝 `nodeId="host"`。否则 helper 能以
  `host` 注册，覆盖内置记录（`host_node` 变 false），随后 `deregister` 就能删掉它——
  别处对 host 节点的保护都建立在"这个 id 不是 helper 的"之上。
- **bad grant 只有一种错误文本**：unknown / 已用过 / 已过期不做区分。`node_register`
  是唯一一个无凭证可达的入口，区分它们等于告诉陌生调用方哪次猜测更接近。
- **`registering` 是真的状态**：register 先写 `registering`，插入 session 后再提升
  为 `online`，所以不存在"显示 online 但拿不到 token"的窗口；中途崩溃留下的
  `registering` 由 `sweep` 过期。
- 所有新凭证比较用**常量时间比较**（`subtle` 或手写 XOR 累加），避免时序侧信道。
  注意：**主 token 的比较仍是 `==`**（既有代码），本 PR 没有改它——这条常量时间
  承诺只覆盖新增的 session token 路径。

## 测试计划

**Rust 单测（`cargo test --workspace`）**

1. `NodeRecord` serde round-trip；`NodeStatus` 小写 wire 形态固定。
2. `node_enroll` → `node_register` → `sessionToken` 可用；主 token 与 session token
   权限不同：session 调 `list_containers` 必须 403。
3. enroll token 一次性：第二次 `node_register` 用同一 enrollToken 失败。
4. 心跳 epoch：旧 epoch 拒绝；`online → offline` 超时迁移；host node 永不过期、不可注销。
5. 常量时间比较函数的基本性质。
6. `command_surface` 两个守门测试保持绿（A 阶段不加 Tauri 命令，前端不变）。

**实机（Windows + WSL guest）**

1. 用 discovery 主 token 调 `node_enroll` 拿 enrollToken/controlUrl。
2. 在 WSL Ubuntu 里跑 `box-helper`（用 Linux target 编出的可执行文件），
   确认 `node_list` 出现一条 `online` 的 `wsl2/linux-x64` node。
3. 订阅 `GET /events?token=<session>`，确认收到 `node_registered` 与 `node_log`。
4. 停掉 helper，等 >90s（或把测试阈值调小）确认 `node_list` 变 `offline` 且记录保留。
5. 重启 daemon（换新 token/epoch），确认 helper 重新 enroll 后恢复 `online`。
6. host 容器（无 `runtime` 字段）start/stop/rebuild/delete 全流程零回归。

**跨平台编译**：Windows `cargo test --workspace`、WSL Linux `cargo check -p dshboxd -p box-helper`。
macOS 无 target，按既有 cfg 规则推理 + `rustc` 最小展开验证不改现有门控。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 改 `main.rs` token 分支影响所有现有 RPC | 主 token 路径保持原样，只追加 `else if` 限权分支；单测 + 实机回归 |
| session token 落进 guest 后能调全部 RPC | 白名单 `NODE_METHODS` + 单独 `validate_session`；单测覆盖 403 |
| daemon 重启 token 轮换导致 helper 永久掉线 | `epoch` + 重新 enroll；实机验证 |
| NAT 模式 `127.0.0.1` 不通 | enroll 时由控制层算好 `controlUrl` 注入；A 阶段在 mirrored 模式实测，NAT 记 TODO |
| SSE snapshot 加了 `nodes` 破坏前端 | 前端只按已知 event 名处理，未知字段忽略；`snapshot` 里多一个 key 是加法 |
| 巡检线程在 daemon 退出时残留 | 用 `shutdown_requested()` 协作退出，随 daemon 进程结束 |
