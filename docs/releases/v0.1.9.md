# DSH Box 0.1.9

**简体中文** · [English](#english)

---

## 简体中文

这个版本把 DSH Box 变成一个容错极高的开发沙盒：在容器里改坏东西，坏掉的是沙盒，不是你在用的桌面端——DSH 的界面、插件和 agent 全都在里面跑，崩了不过是重启一个容器。与此配套，容器可以自己声明环境变量，宿主只说一种模块世界的语言，资源副本知道该去哪个版本的位置。

### 容器内的 agent：21 个 `box_*` 工具

沙盒之所以容错极高，是因为在里面干活的人不必出来。此前 agent 驱动 Box 只有 CLI 一条路——而跑在容器里的 agent 没有 shell。新的 `@nexus-aethra/dsh-box-sandbox` 宿主插件在它运行的 DSH 宿主上注册 21 个带类型的工具：

- **驱动 Box 本身（11 个）**：`box_overview`、`box_lifecycle`、`box_build`、`box_create`、`box_templates`、`box_plugins`、`box_resources`、`box_workspace`、`box_settings`、`box_task`、`box_set_viewport`。
- **在无头浏览器里调试页面（10 个）**：`box_page_text` 列出屏幕上有什么，`box_click_element`、`box_type_text`、`box_press_key`、`box_scroll`、`box_click_at`、`box_close`、`box_screenshot`、`box_set_browser`、`box_console`。

不需要 shell、不需要第二条连接、不需要在容器里装任何东西。插件通过 Box 启动时写下的 discovery 记录找到后台服务，端口和 token 每次启动重新生成，所以重启对它是透明的；所有调用走的是 CLI 和界面共用的那条 loopback `POST /rpc`，任务进度来自同一条 SSE 流。

三种装法，写在 Settings 的 **Agent development** 面板里：从**资源 → 插件**的资源库导入、`pnpm add @nexus-aethra/dsh-box-sandbox` 直接装进 profile、或按容器 `dshbox plugin install <container> @nexus-aethra/dsh-box-sandbox`。

于是"在沙盒里开发 DSH"第一次是闭环的：构建、起停、看页面、读控制台、搬资源状态，全都在容器里完成——不用开第二个终端，也不用把 host 的 shell 交出去。

### 容器环境变量：boxfile 里的 `ENV`

`ENV key=value` 是 docker `-e` 的等价物：变量被烤进封存模板，宿主启动时覆写它本来会继承的环境，于是容器不再依赖调用方当时恰好 export 了什么。键名必须像 shell 变量名（`[A-Za-z_][A-Za-z0-9_]*`），同一个键后声明者胜。

优先级有一条硬边界：**声明值盖过宿主继承值，但 Box 自己的变量（`DSH_HOME`、loopback 端口与 token、工具链路径）仍然优先**——boxfile 无法把 daemon 引去别处。

### 宿主不再劈成两个模块世界

此前宿主以 `node --import tsx/esm apps/cli/src/bin.ts` 启动，而 `tsconfig.base.json` 把每个一方包映射到 `src`，遵循 `package.json` `exports` 的插件行加载器却把同一个包从 `lib` 读。两份拷贝各造一个 `Symbol`，`dsh-tools` 调度器因此按一个 Symbol 存入、按另一个查找：每次 agent tool call 在 `tool/call` 后约 1 ms 死去，界面上只表现成一秒中断，而不是崩溃。

现在启动 `apps/cli` 自己声明的入口 `lib/bin.js`，进程里不放 transpiler；该入口同时进入产物检查——缺它的树会被重建，而不是用坏的方式启动。

### 资源 slot 按版本解析

0.1.7 把 provider 路由从 `settings.yaml#llm-pi-ai` 搬进 `profiles/<profile>/cordis.patch.yml` 的 layer item，credentials 副本于是对着一个没人读的路径解析。现在 kind part 声明带版本区间的 slot（`slot`/`since`/`until`、路径里的 `{profile}`、承载 layer item `config` 的 `#<id>` section 步骤），按容器解析、记入 `parts.json`，注入时按**目的地**重选。

从 0.1.7 容器提取的副本现在能落进 0.1.6 容器的 `settings.yaml#llm-pi-ai`，与既有路由合并、不动 cordis 文件。插件的 `dshbox.resources` 声明使用同一套字段。

### 升级时会发生什么

Box 是个后台服务，常常比安装它的应用活得更久。装上新版而旧服务还在跑时，两者并不一致——**而正在跑的服务被保留**：RPC 接口只会新增，客户端对旧服务做不到的调用会自行降级，而停掉它的代价是你前一刻刚发起的容器启动或构建。

顶栏现在有一行说明，写明两个构建的 stamp。需要新能力时，从托盘菜单在你选定的时刻重启，而不是应用替你做主。

### 构建期：审批不再写坏自己的 manifest

`dshbox.allow-build` 列的 key 会被 pnpm 原样打印出来，而 Box 把 spec 不加引号地写回 `pnpm-workspace.yaml`。scoped spec 以 `@` 开头——YAML 的保留指示符——于是整个 manifest 停止解析，那个本该批准插件的重试死在自己刚写坏的文件上（`bad indentation of a mapping entry`），构建随后提示你添加 boxfile 里**已经有**的那行 LABEL。

现在按缩进读取 section（紧随其后的 `minimumReleaseAgeExclude` 不再被吞掉）、保留不属于 Box 的行、只剥成对的引号、写入一律加引号。

### 打包与配置修复

- **PATH 里的 `dshboxd` 此前永久回答 "bundled daemon is missing"**：wrapper 去 `<install>/resources/server/<target>/` 找 daemon，而 tauri 的 resource map 从不创建这一层。已改为解析真实布局并把 `DSHBOX_RESOURCE_DIR` 指向安装根。
- **`inherit_proxy` 此前是个没有任何消费点的配置字段**，现在真正决定 8 个代理别名是否进入 clean-room 的包管理子进程（默认继承，可关闭）；它的文档注释一直写着与默认值相反的语义，已修正。
- **打不通的私有 registry 现在会说**：它只会留下 `GET …: fetch failed` 一行，旧的 errno 标记一个都不匹配，镜像告警因此从未触发。现在这一行也被计入。
- **容器启动不再弹你的浏览器**：宿主以 `--no-open` 启动。Box 是服务，它开的界面是你主动要看的 webview。

### 测试范围

`cd src-tauri && cargo test --workspace`：**321 通过 / 0 失败**。两条新回归用例做过「改坏 → 必败 → 还原 → 复绿」的反向验证。构建期修复另用捆绑 pnpm 直接验证：把 Box 真实函数写出的 manifest 喂给它，scoped 插件的 `postinstall` 确实执行，改回裸写法立刻 `bad indentation`。实盘 `dshbox build`（8 个 `@deepseek-ai/*`，失败点原本固定在第 6 个插件）exit 0，`bad indentation` 出现 0 次。三个平台的安装包都在 CI 里完整构建过一遍。

## English<a id="english"></a>

This release turns DSH Box into a highly fault-tolerant development sandbox:
break something inside a container and what breaks is the sandbox, not the
desktop you are working in — DSH's UI, its plugins and its agents all run in
there, and a crash costs you one container restart. Alongside that, a container
can declare its own environment, the host speaks one module world instead of
two, and a resource copy knows which version's location to resolve against.

### An agent inside a container: 21 `box_*` tools

The sandbox is fault-tolerant because whoever works inside it never has to come
out. An agent could only drive the box through the CLI — and an agent running
inside a container has no shell. The new `@nexus-aethra/dsh-box-sandbox` host
plugin registers 21 typed tools on the DSH host it runs in:

- **Driving the box itself (11)**: `box_overview`, `box_lifecycle`, `box_build`,
  `box_create`, `box_templates`, `box_plugins`, `box_resources`,
  `box_workspace`, `box_settings`, `box_task`, `box_set_viewport`.
- **Debugging a page in a headless browser (10)**: `box_page_text` to list what
  is on screen, `box_click_element`, `box_type_text`, `box_press_key`,
  `box_scroll`, `box_click_at`, `box_close`, `box_screenshot`, `box_set_browser`,
  `box_console`.

No shell, no second connection, nothing installed inside the container. The
plugin finds the background server through the discovery record the box writes
at startup; the port and token are minted per launch, so a restart is invisible
to it. Everything crosses the same loopback `POST /rpc` the CLI and the UI use,
and task progress arrives on the same SSE stream.

Three ways to install it, all written down in the Settings pane under **Agent
development**: import it from the repository under **Resources → Plugins**,
`pnpm add @nexus-aethra/dsh-box-sandbox` straight into a profile, or
`dshbox plugin install <container> @nexus-aethra/dsh-box-sandbox` per container.

Which makes developing DSH inside the sandbox a closed loop for the first time:
build, start, stop, look at the page, read the console, move resource state —
all of it from inside the container, with no second terminal and no host shell
handed over.

### Container environment: `ENV` in a boxfile

`ENV key=value` is the docker-style `-e` equivalent: the variable is baked into
the sealed template and applied on top of the environment the host would
otherwise inherit, so a container no longer depends on whatever the caller
happened to have exported. A key must look like a shell variable name
(`[A-Za-z_][A-Za-z0-9_]*`) and the last declaration of a key wins.

The precedence has a hard edge: **a declared value beats what the host would
have inherited, but Box's own variables — `DSH_HOME`, the loopback port and
capability token, the toolchain paths — are applied after and cannot be
redirected by a boxfile.**

### The host no longer splits into two module worlds

The host used to start as `node --import tsx/esm apps/cli/src/bin.ts`, while
`tsconfig.base.json` maps every first-party package to `src` and the plugin row
loader — following `package.json` `exports` — reads the same package from `lib`.
Each copy creates its own `Symbol`, so the `dsh-tools` scheduler was stored
under one and looked up under the other: every agent tool call died about a
millisecond after `tool/call`, which the UI rendered as a one-second
interruption rather than a crash.

It now launches the entry `apps/cli` declares (`lib/bin.js`) with no transpiler
in the process, and that entry is part of the artifact checks — a tree without
it is rebuilt rather than launched the broken way.

### Resource slots resolve per version

0.1.7 moved the provider route out of `settings.yaml#llm-pi-ai` into a layer
item of `profiles/<profile>/cordis.patch.yml`, so a credentials copy resolved
against a path nothing reads any more. A kind part now declares a
version-bounded slot — `slot`/`since`/`until`, `{profile}` in the path, and a
`#<id>` section step that travels a layer item's `config` — resolved per
container, recorded in `parts.json`, and re-picked against the destination on
injection.

A copy extracted from a 0.1.7 container now lands in a 0.1.6 container's
`settings.yaml#llm-pi-ai`, merging beside the route already there and leaving
the cordis file alone. Plugin `dshbox.resources` declarations take the same
fields.

### What happens on upgrade

The box is a background service, so it often outlives the app that installed it.
Install a newer DSH Box while the previous one is still running and the two do
not match — **and the running server is kept**: the RPC only grows, the client
falls back for anything the older daemon cannot do, and the cost of stopping it
would be a container start or a build you asked for a moment earlier.

A line in the topbar now says so, naming both builds. When a feature needs the
newer server, restart it from the tray menu at a moment you chose, not one the
app picked for you.

### Build time: an approval no longer corrupts its own manifest

pnpm prints the key it wants, and Box wrote that spec back into
`pnpm-workspace.yaml` unquoted. A scoped spec starts with `@`, a YAML reserved
indicator, so the whole manifest stopped parsing and the retry meant to approve
the plugin died on the file it had just corrupted (`bad indentation of a mapping
entry`) — after which the build asked for the very LABEL line the boxfile
already had.

The section is now read by indentation (so the `minimumReleaseAgeExclude` pnpm
appends right after it is not swallowed), lines Box does not own are kept, only
a matching pair of quotes is stripped on read-back, and every key is quoted on
write.

### Packaging and configuration fixes

- **`dshboxd` on PATH answered "bundled daemon is missing" permanently.** The
  wrapper looked for the daemon under `<install>/resources/server/<target>/`, a
  level tauri's resource map never creates. It now resolves the real layout and
  points `DSHBOX_RESOURCE_DIR` at the install root.
- **`inherit_proxy` was a config field nothing read.** It now decides whether
  the eight proxy aliases reach the clean-room package-manager child (inherited
  by default, opt-out); its doc comment had claimed the opposite of its default.
- **An unreachable private registry now says so.** It leaves exactly
  `GET …: fetch failed` behind, which matched none of the errno markers, so the
  mirror warning never fired. That line is now counted.
- **Starting a container no longer opens your browser.** The host is spawned
  with `--no-open`; a box is a server, and the UI it serves is a webview you
  asked for.

### Testing status

`cd src-tauri && cargo test --workspace`: **321 passed, 0 failed**. Two new
regression tests were reverse-verified (break the fix → the test fails, restore
→ it passes). The build fix was additionally checked against the bundled pnpm
itself: given the manifest the real writer produces, a scoped plugin's
`postinstall` runs, and the bare form fails with `bad indentation` again. A
live `dshbox build` over eight `@deepseek-ai/*` plugins — whose failure point
used to be pinned at the sixth — exits 0 with zero `bad indentation` lines. The
three installers were built end to end on Windows, Linux and macOS.
